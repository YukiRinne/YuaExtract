## 2. 本轮做了什么

### ① 扩展集档案（内核）—— `CxdecExtractorLoader\ExtensionSet.{h,cpp}`

把「动态采集 + 还原成果」固化成一个**可留档的单一档案** `rules.int`，使**同一部游戏**以后重解包时**不用再跑一遍游戏**。

- **格式**：magic `'YXS1'` + 版本 + flags(bit0=zlib) + chunk 表（id/flags/offset/size）+ CRC32；chunk = `META` / `IDENTITY` / `DIRS` / `FILES` / `EXCEPTIONS` / `RULES`(预留) / `STATS`；**未知 chunk 跳过**。压缩用仓库自带 zlib（`CxdecRepacker\third_party\zlib`，**未引第三方依赖**），SipHash 直接复用 `CxdecRepacker\crypto\siphash.cpp`。
- **三层结构**：L1 规则层（二期）/ L2 名字层 / **L3 哈希层默认不存**（加载时用盐重算）→ 实测 20 条档案 734 B（压缩），名字层 12.7 B/条。
- **生成期自校验（核心保险）**：每条「名字 + 盐 → 重算哈希」必须等于采集到的哈希，不等的一律进 `EXCEPTIONS` 并计数 —— 最坏只是补不上，**不会补错**。
- **归属校验**：`exe 摘要命中` → `ExeMatch`；`摘要不中 + 盐一致` → `SaltMatch`；**盐不一致 → 拒绝**；`摘要不中 + 拿不到当前盐` → 默认拒绝，显式 `allowUnverified` 才放行且 `match=Unverified`（**绝不声称盐一致**）。失败性质由 `LoadFailure{None,Structure,SaltMismatch,Unverified,BadArgument}` 区分 —— **结构损坏与"别的游戏"是两类，出路完全不同**。
- 另有：`WriteStaticHashMap`（写 `StaticHash.lst`）、`DryRun`（只读干跑）、库 `InstallToLibrary`/`EnumerateLibrary`（`<库根>\<会社>\<作品>\rules.int` + `manifest.txt` upsert，主键 = exe 摘要）。

## 3. 关键架构事实（新会话必须知道）

**「扩展集」= 一部作品的「名字 ↔ 哈希」知识档案**，用于**免跑游戏**地还原同名游戏的资源名。

```
模式1（该作扩展集提取）        传统动态模式（既有）
  步骤1 生成静态 Hash 表         步骤1 提取动态 XP3 资源
  步骤2 提取动态 XP3 资源        步骤2 加载动态 Hash 收集模块（要跑游戏）
  步骤3 用静态 Hash 还原         步骤3 用动态 Hash 还原
        ↑ StaticHash_Output            ↑ StringHashDumper_Output
```

- **哈希不可跨作移植**：`file_hash = BLAKE2s-256(UTF16LE(名字 + 盐))`、`domain_hash = SipHash-2-4(UTF16LE(目录 + 盐), key=0^16)`（**目录要小写 + 结尾斜杠，结果字节反转**），而**盐每游戏不同** → 档案存**名字**、加载时用**档案内嵌的盐**重算哈希。
- **盐的两处来源**：`<工具目录>\Log\Universal.log` 的 `Hash Seed:`（= 运行时 `HasherSeed`）→ `ExtractKey_Output\Static\*.json` 的 `hash_domain`（静态派生，**离线**）→ 都没有就**明确报错**。空串盐**合法**（与 `Yua::Miner::ReadSalt` 有意不同）。
- **工作区 = 游戏目录**（未变），新增第 4 个产物目录 `StaticHash_Output`；草案在 `<工作区>\ExtensionDraft\`，库在 `<工具目录>\ExtensionLibrary\`（一期**不做** ini 持久化；工具目录不可写时安装**明确报错**）。
- **还原内核零改动**：`Restore::WindowOptions::HashDirectory` 本来就是传参，模式1 只是换个值。
- **"哈希名文件"口径**：只有「最后两段 = 16 位目录哈希 + 64 位文件哈希」才算；**包根下裸 64 位哈希文件不算**。成功率 = 整路径可还原 ÷ 哈希名文件数。
- **干跑面板四行**：可解目录（去重）/ 文件名可解（**按 64 位哈希去重**）/ 整路径可还原 / 成功率 —— ② 与 ③ 不是同一个数，别混。
- **布局/可见性铁律（本轮血泪）**：改可见性或位置之后**必须整窗重绘**（`RDW_ERASE | RDW_ALLCHILDREN | RDW_UPDATENOW`），否则**分组框内部会留下旧像素**；单用 `InvalidateRect` 不够。**任何 hide→show 的布局重排都要自己存/还焦点**（系统不会还给你），且还焦点前必须 `IsWindowVisible` 守卫（别把焦点抢给刚被故意藏掉的控件）。
