# 审计修复说明（2026-11）

本文件只说明**用户会观察到的默认行为变化**与本轮安全修复的验证边界；
旧的交接记录与验证结论不改写。

## 1. 原生代码执行：默认拒绝，逐次显式授权

- `CxdecKeyStatic` 的旧导出 `ExtractKey` 仍然可绑定，但**默认不执行游戏内嵌原生代码**，
  会返回"需要显式授权"且**不创建输出目录/临时 DLL**。
- 需要执行时用 `ExtractKeyEx(exe, out, DWORD flags, error, size)`；**仅 bit0 合法**，
  其余位一律拒绝。`flags = 0` 等价于安全默认。
- GUI 的「静态 Key 提取」在调用前会弹 YES/NO，明确展示目标 EXE 全路径、输出目录、
  "将执行内嵌 DLL"、"工具进程权限"、"仅可信合法副本"、"不构成沙箱"。
  点「否」什么都不生成；自动归属失败后的重试同样要先过这个确认，取消不会自动重试。
- CLI `keystatic` / `keys` / `repack` 需要显式 `--allow-native-code`；未授权且缺少参数时
  明确失败，不静默生成错误的内置参数包。
- **这不等于沙箱**：允许执行后，游戏内嵌代码与本工具同进程、同权限、同地址空间。

## 2. 封包参数派生

- `CxdecRepacker` 的旧 `Repack` / `DeriveKeys` 固定按安全默认（flags = 0）工作。
- 新入口：
  - `RepackEx(..., int rescramble, DWORD flags, ...)`：flags 位于 `rescramble` 之后，`@48`；
  - `DeriveKeysEx(exe, root, DWORD flags, note, noteSize, error, errorSize)`：`@28`。
- 仓库里已有同 EXE 参数、或游戏目录旁已有同名 `hxv4p` 时，无需原生执行即可复用。
  目标 EXE 给了但参数不可得且未授权时**明确失败**，不再悄悄回落到内置参数；
  未指定 EXE 时保留原有内置参数行为并提示。
- GUI 封包在开始前会说明"可能需要执行内嵌原生代码"，YES 才传 flags bit0；
  不后台、未经提示地派生。

## 3. 启动 / 备份 / 注入

- 反篡改流程只有在**本次**成功保全当前 `steam_api.dll` 后才替换：
  使用唯一备份名（含进程/时间戳），`MoveFile` 失败立即中止；
  暂存复制 + 原子替换，后续脱壳/注入/预检失败会回滚。
  已有的旧 `.bak` 不被当作"当前已保全"，也不会被覆盖。
- 替换前有明确确认，列出被修改路径与备份策略；无壳游戏不会静默替换 DLL。
- 注入流程检查远程 `LoadLibraryW` 的线程退出码（x86 HMODULE 非 0）：
  分配/写入/建远程线程/恢复线程任一步失败都会关闭句柄、终止**本次自建的挂起子进程**，
  不再把"游戏已起来了但模块没进去"当作成功。
- 反篡改预检的等待从无限改为**60 秒有界**；超时只终止预检自己创建的工作副本并回滚，
  不会误杀用户已有游戏进程。

## 4. 运行时模块生命周期

- AntiMalform / StringDumper / HashRestore / KeyDumper 在安装 hook / 起始线程前，
  用 `GetModuleHandleExW(FROM_ADDRESS | PIN)` 把自身模块钉在进程生命周期内。
- 当前产品**不支持动态卸载**；不会在 `DllMain` 里做跨线程等待，也不会盲卸 Detours
  造成 loader-lock 死锁。纯工具 DLL 的普通加载/释放不受影响。

## 5. 界面任务生命周期

- 后台任务激活时，目标切换、模式切换、清理、生成、测试、安装等动作与相关控件会被拒绝/禁用；
  busy 检查发生在任何 `SyncTarget` / `ResetJob` / 磁盘改动之前。
- 工作线程只读启动时快照；结果在 `Done` 后由界面线程读取，并带任务序号，
  旧任务的迟到进度/完成消息不会影响下一轮。
- 关窗等待不把超时当线程结束：只有 `WAIT_OBJECT_0` 才关句柄；超时保留句柄与锁，
  窗口保持打开由定时器重试，不使用 `TerminateThread`。
- 还原窗口：选项在启动时快照，工作线程**不再** `SendMessage(BM_GETCHECK)`；
  停止后不再取队列中的后续封包；第二遍不按目标路径跳过，而是把第一遍
  「源 → 实际目标」记录交给内核，同源新目标由内核判 dup，旧哈希后缀清理只针对本源旧落点。
- 在线更新：下载与校验使用同一份内存字节（`VerifyArchiveBytes` + `InstallBytesToLibrary`），
  不再"校验 A、安装 B"；拉索引不创建暂存目录；只在 worker 真退出后清本次 owned 暂存目录；
  入库覆盖确认会列出所有同槽位或同 EXE 的旧项。
- 在线更新写库前做最终复核：覆盖确认框是模态的，期间新到达的 WM_CLOSE / 取消
  （`ClosePending` / `Cancel` / `Closing`）会再次被 `OnlineInstallRecheckAborts` 拦住，
  即使 worker `Ok=true`、用户刚点「是」，也不会 `InstallBytesToLibrary`，只清本次 staging。
- 主界面控件锁定与命令门禁共用同一份 sensitive ID 列表；`SETM_NOTE`、`SET_OPEN_LIB`、
  `ADVANCED`、打开工作区/还原目录/报告等只读但会弹模态框的命令，在
  `JobActive / ClosePending / JobDoneUi` 期间同样拒绝。
