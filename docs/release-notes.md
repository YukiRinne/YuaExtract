### 修复：切到「制作扩展集」后画面残留首页控件像素（YuaExtract · 2026-10-14）

从「首页」点「制作扩展集」后，**首页控件的旧像素留在画面上**，与制作页签的控件叠成两层。

- **根因**：窗口里的分组框（`BS_GROUPBOX`）只画边框和标题、**从不擦除内部**；而父窗口又被 `WS_CLIPCHILDREN`
  挡在外面 —— 于是"控件还没显示时被别的控件画过的像素"永久留在分组框里。**控件可见性本身一直是正常的**，
  所以此前所有基于"控件是否可见"的检查都发现不了它。
- **修法**：每次布局重排前先把子控件**全部隐藏**（枚举，不维护名单），整块客户区擦成背景色，再布局并统一决定可见性，
  最后整窗（含子控件）重绘；切页签走同一口径。顺带保留键盘焦点，并修掉"拉大窗口"路径的同类残留。
- **验证**（两个独立口径）：修复前差异 **2.84%**（整窗）/ **1.369%**（客户区）→ 修复后 **0 像素**；
  新增 **E-11 像素级回归断言**（含"修复前旧构建抓图必须炸"的自检），`-Scope all` **104 / 104**。
- **顺带**：标题栏与「关于」页新增**构建指纹**（如 `YuaExtract 1.0.0 [492522BD]`），以后一眼能看出在跑哪个构建；
  验证脚本加了"假绿护栏"（没有本轮结果时拒绝报通过）。

### 新增：扩展集一期（YuaExtract · 2026-10-13）

把「动态采集 + 还原成果」固化成一个可留档的档案，**同一部游戏以后解包还原不用再跑一遍游戏**。

- **档案 `rules.int`**：magic `'YXS1'` + chunk 表 + CRC32 + zlib；**只存名字**（目录 / 文件），
  哈希在加载时用档案内嵌的盐重算 —— 实测 20 条档案 734 B，名字层 12.7 字节/条。
- **「制作扩展集」页签**：生成（合并采集日志与各 `*.lst` → 归一化 → **生成期自校验** → 落盘）、
  编辑信息、测试（**只读干跑**出成功率）、安装到扩展集库（`<工具目录>\ExtensionLibrary\<会社>\<作品>\`）。
- **首页模式1「该作扩展集提取」**：生成静态 Hash 表 → 提取动态 XP3 资源 → 用静态 Hash 还原资源名；
  **全程不启动游戏**。
- **归属校验**：exe 摘要命中 → 直接用；盐一致 → 可用并标注；**盐不同 → 拒绝**；拿不到盐 → 默认拒绝，
  可显式"强行使用"且**面板与日志长期写明"未能校验归属"**。
- **验证**：`run-all.ps1 -Scope extension` **33 / 33**、`-Scope all` **86 / 86**；
  独立验证报告见 [`../_verify/restore-harness/VERIFICATION-扩展集.md`](../_verify/restore-harness/VERIFICATION-扩展集.md)。

## 这个版本有什么

### 新增：XP3 重封包（`CxdecRepacker`）

- **目录 → XP3**：把解包出来的资源目录重封成包，条目顺序与每文件密钥照原包还原。
- **可逐字节复刻原件**：未改动的解包目录重封后与原件 **SHA256 完全相同**
  （实测某 119 条目、367 MB 的档案）。这既是能力，也是**封包正确性的自检标准**。
- **支持做补丁包**：覆盖包里已有资源；补丁文件名按发行版区分
  —— 国际版用 `patch.xp3`，日版新框架那批用 `patch@r<N>.xp3`。

### 修复：补丁包"引擎读不出来"的三处根因

症状是包被封进去、引擎也加载了，但资源读不出来：轻则不显示、不报错，
重则脚本抛 `Cannot convert the variable type ((void) to Object)` 之后崩。

1. **索引条目名必须是占位名**（`U+5000+序号`）。写真实文件名会让引擎按名字走捷径、
   绕开 Hxv4 映射表，于是拿不到该条目的每文件密钥，读出来是还带着内容层变换的字节。
2. **描述符 `flags` 的 bit0 必须为 0**。它只用来选解密 nonce；拿它去改内容层过滤器的
   推导方向，会导致引擎按 0 解、密文全乱。
3. **每文件密钥优先沿用原包**。密钥是打包方自由挑的数据，解包清单里已经记着原包那把。

### 变更：日志统一到 `Log\` 目录

- 之前会话日志散落在注入 DLL 目录、游戏目录、各模块输出目录下（共 9 处）；现在全部写在
  **`loader.exe` 同级的 `Log\`**，UTF-8，行格式固定为 `时间 | 级别 | 线程 | 正文`。
- 失败行带上 Win32 错误码与出错步骤（`stage=Open`、`code=5(ERROR_ACCESS_DENIED)`），
  "写失败"不再是一句无从判断的话；解包是多线程跑的，行首的线程号能区分是"同一个域一直失败"
  还是"几个线程各失败一次"。
- 每次运行保留上一代（`.1`）；单个日志的日志行有 32 MiB 上限，超过后留一条截断提示。
- 注意区分：`DirectoryHash.log`、`FileNameHash.log`、`HashRestore_Report.tsv` 是**产物**
  （后续流程会读回去），仍留在各自的输出目录，不随日志搬家。

### 新增：开发调试命令行（`CxdecCli.exe`）

不用点界面的调试入口，位于 `CxdecExtractordll\`，可做目录形态判定、封包、参数派生、
静态取 Key，以及逐字节比对（复刻验证时直接报首个差异偏移）。它按自己的模块目录找
同目录的 DLL，**不要单独挪走**。

### 文档

- 新增 `docs/hxv4/` 六篇：容器与索引结构、资源名与哈希、数据层密钥与过滤器、
  封包实践、离线自检方法、参数派生与 `.hxv4p`；`docs/README.md` 作为分类索引。
- 其中"离线自检"一节给出了不开游戏就能定位问题的方法（锚点法、两种 `open_flag`
  对解、逐条对比、引擎崩溃日志位置）。

## 环境

- 系统：Windows 7 SP1 x64 及以上，推荐 Windows 10 / 11
- 目标游戏为 32 位程序，本工具同样是 **x86**

## 用法速览

1. **解包**：选择游戏主程序 → 启动 → 在解包界面拖入一个或多个 `*.xp3` 排队处理；
   输出目录里同时生成 `.alst` 清单（域哈希 / 文件哈希 / 每文件密钥）。
2. **恢复资源名**：用运行时恢复或 Hook 撞库两种方式，把纯哈希目录还原成可读文件名。
3. **封包**：选择游戏主目录 → 指定要封的目录与输出文件名 → 封包。
   做补丁时建议先用解包目录验证一次（未改动的目录重封后应与原件哈希一致），再替换资源。
4. **密钥派生**（静态密钥提取）：无需启动游戏、无需注入，从游戏 EXE 与 BOOTSTRAP
   模块派生 Hxv4 解密所需的完整参数；同一款游戏只需派生一次。
